# tmux 交接 tab 被强制英文 — 2026-11-17

## 现象与根因（有证据）

用户反馈：在 tmux 新开 Pi 交接 tab 后无法输入中文，被强制切到英文输入源。
复现面仅限这类新开的 Pi tab；从交互 fish 启动 Pi 的 tab 正常。

只读取证（状态 JSON / tmux / ps，不改 IME、不重启服务）：

- 目标 pane `%2`：外层 `fish` PID 37335 与 Pi PID 37341 **共用 PGID/TPGID 37335**；
  主窗口 tab `%1` 的 Pi 32895 自带 PGID（job control），因此一直正常。
- Pi 元数据 `editing: true`、pane `%2`、socket 均正确且在 7 秒租约内。
- `input-method/tmux-update.py` 把 `tpgid` 直接写入 `foreground_pid`；策略按
  `ctx.pid == foreground_pid` 匹配，`37341 != 37335` 导致误判非编辑区，
  Hammerspoon 状态 `desired = ABC`，持续强制英文。
- `fish -c pi`（tmux 常用启动方式）属于非 job-control 交互，Pi 不会成为
  进程组组长，所以 tpgid 恒等于 fish 的 PGID。这是结构性缺陷，不是租约/
  prefix/标题身份问题；该 pane 的 `pane_in_mode=0`、`client_key_table=root`。

## 修复（reporter + policy 双层，按用户硬性要求）

用户要求：**无论 Pi 以何种方式出现，焦点在 Pi 编辑区就必须是中文**。
因此 PID 识别降级为“精确优选”，不得成为中文的必要条件：

- policy（`macOS/private/input-method/policy.lua` 与
  `NixOS/desktop/input-method/policy.py`）：先按 PID 精确匹配（行为不变），
  不中则按容器身份兜底——tmux pane+socket、WezTerm pane、Ghostty surface——
  仍要求 editing=true + 7 秒租约新鲜。因此 `fish -c pi` 进程组错位、报告器
  缺口、Pi 重启 PID 漂移都不会再强锁英文。隔离不变：其他 pane/窗口/租约过期/
  编辑框失焦仍为英文；原生路径的无键记录不允许跨进程兜底（防另一窗口借用）。
- reporter（`System/Common/input-method/tmux-update.py`）：以前台进程组+TTY+
  同 pane/socket 新鲜租约解析真实 Pi PID，作精确优选；歧义/无记录时保留
  旧行为（此时 policy 兜底接管）。

回归：两端 policy 测试新增 PID 漂移→中文、过期→英文、精确优先、无键原生
记录不跨窗口；`tests/tmux-foreground.py` 13 项覆盖 reporter 识别与快照字段。
