# tmux 交接 tab 被强制英文 — 2026-11-17

## 现象与根因（有证据）

用户反馈：在 tmux 新开 Pi 交接 tab 后无法输入中文，被强制切到英文输入源。
复现面仅限这类新开的 Pi tab；从交互 fish 启动 Pi 的 tab 正常。

只读取证（状态 JSON / tmux / ps，不改 IME、不重启服务）：

- 目标 pane `%2`：外层 `fish` PID 37335 与 Pi PID 37341 **共用 PGID/TPGID 37335**；
  主窗口 tab `%1` 的 Pi 32895 自带 PGID（job control），因此一直正常。
- Pi 元数据 `editing: true`、pane `%2`、socket 均正确且在 7 秒租约内。
- `input-method/tmux-update.py` 把 `tpgid` 直接写入 `foreground_pid`；策略按
  `ctx.pid == foreground_pid` 匹配，`37341 != 37335` 导致误判非编辑区，
  Hammerspoon 状态 `desired = ABC`，持续强制英文。
- `fish -c pi`（tmux 常用启动方式）属于非 job-control 交互，Pi 不会成为
  进程组组长，所以 tpgid 恒等于 fish 的 PGID。这是结构性缺陷，不是租约/
  prefix/标题身份问题；该 pane 的 `pane_in_mode=0`、`client_key_table=root`。

## 修复（仅共享 reporter，不扩策略）

`System/Common/input-method/tmux-update.py`：

- 新增纯函数 `process_table` / `foreground_pid`：以前台**进程组**为边界，
  只在该组 + 同 TTY + 同 pane + 同 socket（realpath 归一）+ 新鲜租约的 Pi
  元数据中解析真实 Pi PID；歧义或无记录时保留原“组 leader”行为。
- reporter 只做身份识别，不复制 IME 策略；editing/prefix/copy-mode/租约仍由
  两端 policy 决定。不读取命令行/提示文本；快照仍只含既有元数据字段。
- 兼容 macOS `ttysNNN` 与 Linux `pts/N`；`realpath` 处理 `/private/tmp` 差异。

`tests/tmux-foreground.py`（13 项）：非 job-control fish 子进程、交互 job、
Linux tty、后台 Pi、错误 TTY/pane/socket、过期/未来/死亡租约、无记录回退、
editing=false 仍识别、歧义回退、坏 ps 行、快照写入保留 policy 字段与 0600 权限。
`tests/tmux-foreground.nix` 实际构建 Nix reporter 并用产物路径跑同一测试。
